Support (Zendesk)

Support ticket history — issues raised, resolution time, and satisfaction — linked to the same customer profile as every other channel.

High-Level Design

Zendesk → .NET Core Connector on Azure → downstream activation.

💼 Business Context

  • Support history is one of the strongest churn-risk signals available — unresolved or repeated issues predict cancellation
  • Lets marketing/success teams avoid promotional outreach to customers with an open critical ticket
  • Owned by Customer Support, shared with Customer Success / Retention

🔌 Technical Overview

A .NET Core connector subscribes to Zendesk's ticket webhook events (ticket.created, ticket.solved, satisfaction.rated) and also runs a scheduled Zendesk Search API sync for backfill. Both paths normalize through Cxos.Ingestion.Client into the same ticket-event schema.

🔗 Integration Points

  • Zendesk webhook subscription (ticket lifecycle events)
  • .NET Core scheduled sync (Zendesk Search API) for backfill/reconciliation
  • Cxos.Ingestion.Client NuGet package
  • Reverse ETL — writes CXOS profile context (LTV, tier) into the Zendesk ticket sidebar via a custom app

🧰 Services Consumed

  • Azure Functions (webhook receiver)
  • Azure Key Vault (Zendesk API credentials)
  • Cxos.Ingestion.Client
  • Azure Functions Timer (scheduled Search API backfill sync)
  • Azure Data Lake Storage Gen2 (ticket history)
  • Application Insights
  • Zendesk Webhooks API & Search API (source-side)

⚠️ Non-Functional Considerations

  • Scale: ticket volume is modest compared to behavioral events — a webhook-first design is sufficient without a heavy queue
  • Latency: near-real-time for ticket state changes; satisfaction ratings can lag by hours (customer-driven)
  • Reliability: scheduled reconciliation sync catches any missed webhook deliveries
  • Security/Privacy: ticket body text may contain sensitive account details — redaction rules mirror the call-center transcript pipeline

🎯 Enterprise Example

A subscription business flags customers with an unresolved "billing_dispute" ticket and automatically suppresses them from the next win-back campaign send via the Activation API — preventing a support-driven customer from receiving a tone-deaf marketing message mid-complaint.
